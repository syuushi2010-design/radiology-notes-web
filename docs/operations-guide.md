# 運用ガイド

## 1. Webアプリから使う

### ノートを作る

1. 右下の「新規ノート」を開く。
2. タイトル、要約、本文を入力する。
3. モダリティ、解剖部位、テーマ、タグを必要なだけ選ぶ。
4. Web資料を使った場合は「出典・参考資料」へ資料名とURLを登録する。
5. 画像を追加する場合は、代替テキスト、元ページURL、提供元、権利状態を記録する。
6. 「下書き」または「公開」を選んで保存する。

Webアプリで本人が保存した内容の確認区分は「本人編集」になります。後からCodexへ明示的に確認を依頼し、根拠を確認できた時だけ「Codex確認済み」へ変更します。

### 検索する

- タイトル、要約、本文、タグ、出典名を検索欄から横断検索できます。
- 詳細分類では、モダリティ、部位、テーマ、タグを組み合わせられます。
- 一つの分類内では候補のいずれか、分類間ではすべての条件に合うノートを表示します。
- タグを複数選んだ場合は、選んだタグをすべて含むノートを表示します。

### オフラインで読む

- お気に入りにしたノートと、最近開いたノートを端末内へ保存します。
- 「保存済み」で最終同期時刻を確認できます。
- オフライン中は閲覧と検索だけを行い、編集・復元・お気に入り変更はできません。
- ログアウトすると、IndexedDB、最近閲覧履歴、画像キャッシュを消去します。

### iPhone・iPadのホーム画面へ追加する

1. SafariでGitHub PagesのURLを開く。
2. 共有ボタンを開く。
3. 「ホーム画面に追加」を選ぶ。
4. 追加された「放射線ノート」を起動する。

## 2. Codexへノート化を依頼する

調査、画像探索、ファクトチェックは常時実行しません。次のように明示的に依頼します。

```text
このURLとメモを基に、副鼻腔CTの撮影範囲をノート化して。
公式資料と査読論文でファクトチェックし、適用条件と出典も入れて。
保存可能な参考画像がなければAI模式図を作って。
```

Codexは次のどちらかにします。

- `codex_verified` + `published`: 根拠と適用条件を確認できた
- `needs_review` + `draft`: 根拠不足、矛盾、権利問題などが残る

調査を頼まれていない素材は、勝手にWeb検索や自動公開を行いません。

## 3. Codex同期用フォルダ

作業中のノートは `content/notes/<ノート名>/` に置きます。詳細は [Codex同期用ノート形式](note-folder-format.md) を参照してください。

```text
content/notes/example/
├── note.md
├── meta.json
└── reference-image.webp
```

初回同期:

```sh
npm run sync:note -- content/notes/example
```

既存ノートの同期では、`meta.json` の `version` とSupabaseの最新版を比較します。版が違う場合は上書きせず停止するので、先にバックアップを取り直して差分を確認します。

## 4. バックアップ

### Web画面から手早く書き出す

「設定・データ管理 > Markdownバックアップ」から、全ノートを一つのMarkdownファイルとして保存できます。画像本体は含まれません。

### 画像を含む完全バックアップ

`.env.local` にローカル専用のSupabase Secret keyと本人User IDがある状態で実行します。

```sh
npm run backup:export
```

日付フォルダを指定する場合:

```sh
npm run backup:export -- backups/2026-08-19
```

出力先はGit管理対象外です。Supabase Freeには自動バックアップが含まれないため、内容を大きく更新した日と月1回を目安に実行します。バックアップ先も第三者が読めない端末内または暗号化ストレージに置きます。

### バックアップから戻す

1. 戻したいフォルダの `meta.json` と `note.md` を確認する。
2. 現在のSupabase版と `meta.json` の `version` が一致するか確認する。
3. 同期コマンドを実行する。
4. 競合停止した場合は、Web側最新版を再バックアップし、手作業で差分を統合する。

## 5. 画像の扱い

- `reusable`: ライセンスや公式条件で保存・再利用を確認済み
- `private_unconfirmed`: 条件を確認できず、本人専用画面でのみ参照
- `link_only`: 保存禁止、取得元不明、制限回避が必要などのため画像本体を保存しない
- `ai_generated`: 新規生成した模式図。画面に「AI作成模式図」と表示

Codex同期スクリプトは、`link_only` の画像アップロード、10MB超、未対応形式、外部画像の出典不足を拒否します。リンクだけ残す場合は画像を添付せず、本文または出典へ元ページURLを記載します。

## 6. 変更履歴と競合

- Web編集、お気に入り変更、過去版復元のたびに版番号が増えます。
- 同じ古い版をiPhoneとiPadから更新した場合、後から保存した側は競合エラーになります。
- 詳細画面の「変更履歴」から過去本文を新しい版として復元できます。
- 復元時も現在の出典と画像は維持し、確認区分は「本人編集」へ戻します。

## 7. 定期確認

月1回を目安に次を行います。

```sh
npm audit
npm run verify
npm run backup:export
```

さらにSupabase Security Advisor、GitHub Actionsの失敗、Free枠使用量、画像の権利状態を確認します。
